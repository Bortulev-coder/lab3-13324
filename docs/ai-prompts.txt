ПРОМПТ ДЛЯ GIGACHAT

Нужен метод consume в Java 17 для учебной объектной модели.
Класс RumBottle содержит private int volume и private Person owner,
а также protected final StoryLog log. StoryLog имеет метод
void event(String message). Person имеет name() и equals(Object).
Идентичность владельца проверяй через owner.equals(user).

Сигнатура:
public void consume(Person user, int amount) throws InsufficientRumException

Контракт:
1. Если user не владелец (в том числе null), бросить IllegalArgumentException.
2. Если amount <= 0, бросить IllegalArgumentException.
3. Если amount > volume, бросить проверяемое InsufficientRumException(amount, volume).
4. До завершения всех проверок не менять volume и не писать сообщение об успехе.
5. При успехе уменьшить volume ровно на amount, затем вызвать log.event с
   именем персонажа, расходом и остатком. amount == volume допустимо.
6. Не изменять публичную сигнатуру, не подавлять исключения, не применять
   внешние библиотеки, ввод с клавиатуры, глобальные переменные или случайность.
7. Модель однопоточная. Считается, что log.event не выбрасывает исключений.

Приведи код метода и, если нужен, закрытого вспомогательного метода,
объясни порядок проверок и предложи граничные тесты.
Существующий класс исключения имеет конструктор
InsufficientRumException(int requested, int available).

ПРОМПТ ДЛЯ DEEPSEEK

Постановка совпадает с текстом выше: от «Нужен метод consume» до
описания конструктора InsufficientRumException. Общий контракт
позволяет сопоставить варианты на одинаковых проверках.

МЕТОДИКА СРАВНЕНИЯ

Я выделил из ответов реализации consume и необходимые закрытые методы.
Каждый вариант поместил в отдельную копию проекта в comparison/variants.
В основном варианте сохранил исходный consume. Затем выполнил сборку,
59 проверок модели, 12 общих граничных случаев и дополнительную проверку
имени в журнале. Исходники, различия и вывод программы сохранил в файлах.
Qwen рассматриваю как доработку ранее показанного кода; основное
сопоставление выполняю с реализациями GigaChat и DeepSeek.
Проверки выполнены 4 ноября 2026 года. Полный анализ приведён в отчёте.
