СРАВНЕНИЕ РЕАЛИЗАЦИЙ МЕТОДА CONSUME

Я сопоставил основной вариант метода с реализациями GigaChat, DeepSeek
и Qwen. Для каждого варианта создал отдельную копию проекта, выполнил
одинаковые проверки и сохранил исходники и журналы. Проверка: 04.11.2026.

ПОЛНЫЕ КОПИИ ПРОЕКТА
  variants/main     — исходный контрольный вариант
  variants/gigachat  — метод GigaChat и его formatterConsume
  variants/deepseek  — метод DeepSeek
  variants/qwen      — метод Qwen и его formatterConsume

В каждой папке есть:
  src/lab3/RumBottle.java — фактически проверенный класс;
  остальные исходники модели, тесты, build.sh и build.ps1;
  lab3.jar — собственный исполняемый архив;
  results/compilation.txt — результаты компиляции;
  results/ModelTest.txt — 59 проверок модели;
  results/ConsumeContractTest.txt — 12 общих случаев и проверка имени;
  results/default.txt — фактический вывод обычного сценария;
  results/low-rum.txt — фактический вывод при --rum=5;
  results/environment.txt — версия Java при запуске.

Методы сохранены отдельно в *-method.java.txt. Их логика не исправлена;
нормализованы отступы и пустые строки. Для подстановки сохранён
requireOwner основного проекта, используемый также методом transfer.
Полные классы из ответа Qwen намеренно не подменяют предметную модель.

ДЛЯ ПОВТОРА ВСЕХ ПРОВЕРОК
  Из корня проекта: python comparison/run_comparison.py
  Требуются Python 3.9+ и JDK 17+. Внешние Python/Java библиотеки не нужны.
  Скрипт пересоздаёт генерируемые копии из основной версии и сохранённых
  методов, затем записывает свежие журналы. Правки этих копий перед
  повторным запуском нужно сохранить отдельно.

ОСОБЫЙ ФАЙЛ GIGACHAT
  variants/gigachat/GigaChatCheckedProbe.java — специально сокращённое
  воспроизведение ошибки отсутствующего throws/catch в тестах из ответа GigaChat.
  Он намеренно не компилируется и не входит в штатные src/test.
  Диагностика: results/comparison/gigachat-checked-exception-probe.txt
  Полный набор исходных JUnit/Mockito-тестов не запускался.

ИНТЕРПРЕТАЦИЯ
  Каждый метод: компиляция успешна, 59/59 проверок модели, 12/12 общих случаев.
  В дополнительном случае равных по equals персонажей с разными name
  DeepSeek пишет owner.name(), остальные user.name(). Это явно сохранено
  как LOG_USES_USER_NAME=false в журнале DeepSeek, а не скрыто исправлением.
  Qwen дополняет ранее показанный код; я рассматриваю его как вариант
  доработки. Сравнительные варианты проверены локально; на helios
  я собрал и запустил основную реализацию.
